# 证券池 Excel 导入需求说明

> 前端页面：`security_pool_excel_import.html`  
> 后端前缀：`/api/v1/securityPoolExcelImport`  
> 公共模板下载：`/api/v1/commonFile/downloadTemplate`  
> 角色定位：具备投资池 `excel_importable` 权限的用户，通过 Excel 批量发起**证券**或**主体**池调入/调出。

### 同券关联市场范围

同券关联市场与投资池投资市场共用 `MarketCode` 集合（`SSE/SZSE/NIB/BSE/COMPANY/OTC/HKEX/QDII/JWCW/UNKNOWN/OTHER`），不另设白名单。先按 Wind `EXCHMARKET` 筛选主代码和关联代码，再查询本地主档；范围外代码不参与关联展示、关联校验和关联出入库，缺少主档不阻断，范围内缺少主档或市场仍报错。不按代码后缀或 `S_INFO_EXCHMARKET` 推断；目标池勾选的市场仍是逐券入池限制，不用于裁剪同券集合。证券池、ABS、CRMW、批量、Excel 及临时转正复用同一查询。

## 同券跨市场整组校验

每批统一调入或调出。开启「允许联动与互斥调整」时，同一目标池中已由前面一行展开的同券代码直接复用该组校验结果，导入明细标注并入的原始行。调库结果保留每个实际代码，主体选择沿用发起该组的原始行。

同一 ISIN 的债券按各市场实际代码读取状态、摘牌日及在池情况。调入和调出结果均保留主券及每个关联市场的独立记录。已退市（`D`）、摘牌日早于当天或调出时已不在目标池等可放行的业务失败，仅在对应证券行显示为「调整提示」，该行仍标记为可调整。在途和已在目标池的调入项拦截整组。无法识别关联证券或目标池的数据错误仍阻断整组，不允许跳过这类关联券只提交其他市场。其他独立调库组不受影响。

“放开规则”由主券传递给所有关联券，仅跳过既有主体债入库矩阵规则；在途流程、市场、品种、到期、容量及其他硬限制仍按每个实际代码校验。

人工单笔调入由后端按当前同券关系重新核对各目标池应提交的代码。普通批量和 Excel 复用本次校验结果中的实际代码集合。普通调库提交及终审逐码复核调入，实际提交的代码到期时要求重新校验整组。Excel 提交及终审沿用到期作为调整提示的口径。逐券活动流程检查继续执行。

## 1. 页面概览

单页工作台：上方双卡 + 下方 Tab（导入明细 / 调库校验结果）。

1. **导入参数**
   - **导入类型**：主体 / 证券，默认主体（上传后锁定）
   - **调整方向**：调入 / 调出
   - **导入选项**：**允许联动与互斥**（证券和主体均可勾选，默认勾选）
   - **调整原因**
   - **不选目标池**（目标池由 Excel 父池/子池名称解析）
2. **下载模板并上传**
   - 两个下载按钮：**下载证券模板** / **下载主体模板**
   - 拖拽上传 xls/xlsx（≤5MB），按当前导入类型解析
3. **导入明细** Tab：行级校验状态、筛选、分页；证券行可选择担保人/权益人、ABS 自选权益人并显示主体内评；操作：重置 / 校验
4. **调库校验结果** Tab：对齐证券池批量调整列（简称/代码/池/调整类型/方向/审批流程/说明/可调整）；操作：重新校验 / 提交
5. **提交** → 弹出「选择调库流程」对话框（与批量调整一致）

### 1.1 模板列

| 类型 | 模板编码 | 列 |
|------|----------|----|
| 证券 | `security_pool_import` | 父池名称、子池名称、证券名称、证券代码 |
| 主体 | `company_pool_import` | 父池名称、子池名称、统一社会信用代码、主体全称、主体代码 |

不再包含：市场类型、证券品种、调整人、调整时间。

目标池由「父池名称 + 子池名称」解析为启用叶子池。证券导入两列必填。目标为根级叶子池时，两列均填写该池的实际名称，例如 `CRMW库 / CRMW库`。有父池的目标按实际父子池名称填写。主体根池允许父池为空。每行可对应不同池。

证券代码匹配忽略大小写，校验后回写主档的实际代码用于提交。证券模板不填写评级主体。上传后在「导入明细」中选择，控件和候选口径与「证券池批量调整—可选证券」一致：

- 仅 ABS 上传行初始化首个权益人，已确认或在途主体优先回显。仅 ABS 展示权益人和自选权益人。仅担保债展示担保人和担保人主体内评分。上传时为担保债行优先回显已保存且仍有效的担保人，否则默认选中首项。评分随选择更新。ABS 担保债的担保人选择独立保存，与权益人及自选权益人一起回显。
- **自选权益人**：仅 ABS 展示，按主体代码或名称查询全市场有效主体；无需与当前证券存在关联。
- **主体内评分**：ABS 自选权益人优先；未选择自选权益人时使用关联主体。清除自选后恢复关联主体内评，不清除原关联选择。
- 各导入行独立保存担保人/权益人和 ABS 自选权益人。同一证券代码导入不同池时，上传默认值相同，但修改或清除某一行不影响其他行，翻页和刷新后仍保留各行选择。修改后本批所有行回到待校验，旧校验结果和流程选择清除，须重新校验。
- 默认第一条只在上传时初始化，后续分页和校验不覆盖手动选择或清除。ABS 必须有关联权益人或自选权益人；担保债有候选时必须选择，无关联主体且单券规则不要求选择时允许留空。
- 旧六列模板仍按前四列读取，Excel 中的主体全称和代码不再参与选择；已提交批次不可修改主体选择。

## 3. 接口

| 接口 | 说明 |
|------|------|
| `POST commonFile/downloadTemplate` | `{ templateCode: security_pool_import \| company_pool_import }` → Base64 xlsx |
| `POST securityPoolExcelImport/uploadExcel` | multipart：`request` JSON（含 `importType`）+ `file` + 可选 `originalFileNameListJson`（JSON 数组，单文件时长度 1；兼容公司环境中文文件名乱码） |
| `POST .../queryTask` | 批次信息 + `checkItems` |
| `POST .../queryItemPage` | 明细分页，证券代码或主体代码按前缀筛选，证券行附带类型、ABS 标志、关联候选、已保存选择及最新内评 |
| `POST .../editRatingCompany` | `{ impId, itemId, relatedCompanyCode, selfSelectedRightsHolderCode, currentUserId, pageIndex, pageSize, keyword }`；按导入明细 ID 仅更新当前行，空字符串清除对应角色，并清空本批旧校验快照 |
| `POST .../checkImport` | 内联校验，证券与主体明细每 200 行批量回写校验结果，随后保存批次摘要与 `result_json` |
| `POST .../submitImport` | 提交逐条勾选的调库项，必填 `checkItems`，包含已选手工项的流程选择 |
| `POST .../cancelImport` | 逻辑删除批次 |
| `POST .../queryClearPoolList` | 按当前用户的 Excel 导入权限查询启用叶子池及在池主体、债券数量 |
| `POST .../clearPools` | 按 `poolIds` 清空所选池，成功返回已生效的调库日志 ID |

权限：启用叶子池 + `excel_importable`（管理员 userId=1 放行）。

## 4. 校验与提交口径（分证券/主体两分支，复用既有服务）

Excel 层负责：模板/临时表、父子池解析、`excel_importable` 权限、页面评级主体选择及导入类型分支编排。
**调库可行性与落库逻辑不再自写简化版**，分别委托：

| 分支 | 校验 | 提交 |
|------|------|------|
| 证券 | `BatchSecurityCheckService` 批量取数并执行共用规则（业务失败作为可提交提示，含产品库快速资格） | `BatchSecurityAdjustSubmitService.submit` |
| 主体 | `BatchCompanyAdjustCheckService` 批量取数，复用主体规则 | `BatchCompanyAdjustSubmitService.submit` |

主体导入沿用主体落池链路。Excel 主体调入生效后，主体主项和同批联动产生的在池状态可触发旗下普通债的定时补入。

**强担保豁免开关**：统一使用 `common/constants/BusinessSwitches.java` 中的代码常量 `BusinessSwitches.STRONG_GUARANTEE_ENABLED`，当前为 `false`。改为 `true` 可恢复豁免，修改后需重新编译并重启服务生效。关闭时，非 ABS 担保人内评 1 档也执行重点观察名单限制；开启时恢复原有重点观察名单准入及池间 `in_restrict` 豁免。普通担保债内评取较优值及矩阵规则不变，ABS、禁止池及其他限制池不享受该豁免。 证券导入继续完整执行原规则并将业务失败作为可提交提示；关闭开关会恢复相应重点观察名单提示，不改变导入放行策略。

### 4.1 证券导入

- 上传和每次校验都按 Excel 行序检查「证券代码 + 子池名称」是否重复。去除首尾空格，证券代码忽略大小写。首行继续校验，后续重复行显示「不可调整」并禁选。ABS 主体一致性检查使用去重后的导入行。
- 每行 Excel → 一券 + 一目标池 + 方向。解析目标池后集中读取主档、在途、在池、容量、评级主体等数据，再逐行执行完整校验（含联动、互斥、关联码和流程候选）。清空目标池时，把名单外证券汇总为一批执行出库校验。
- 完整执行业务规则。在途和调入时已在目标池属于硬拦截，整组不提交。其他可识别对象的业务失败保留为调整提示，并沿用原流程候选。无法识别或无权限的对象继续拦截。
- 产品库快速资格及 CRMW 来源开关见 [04 快速入库与本次材料豁免](04-security-pool-adjust.md#快速入库与本次材料豁免)。提交带有 `productSource` 资格的主项时复核主券和关联市场代码的有效来源。
- 上传时按关系优先级及最新内评排序，分别初始化 ABS 权益人和担保债担保人。页面通过代码保存选择，名称由服务端回填；不按 Excel 名称解析，不自动把无效关联选择转换为自选角色。
- ABS 关联权益人写入 `rightsHolderCode`，全市场自选权益人写入 `selfSelectedRightsHolderCode`，两者分别保存且自选优先评级；担保债所选担保人写入 `guarantorCode`。ABS 担保债的导入明细在 `fld020` 独立保存担保人代码。每次校验/提交重新复核候选资格，复用完整单券调库规则计算可调入池。ABS 最终采用的权益人（自选优先）无内评时，调入信用债分级库的校验提示“所选权益人无内评分”，与单券调整一致。
- 修改、校验、提交、取消均按批次号读取当前批次。主体修改后清空本批行级校验及 `result_json`，即使客户端回传旧 `checkItems` 也不能绕过重新校验。
- 提交从本批已通过校验的持久化明细读取各行选择，按 `sourceItemId` 分组。非 ABS 不同导入行继续独立选择；同一 ABS 的跨行主体代码必须一致；本行的主项、联动、互斥和关联项共用该行选择及流程。先统一复核已有在途流程，再逐行落库，避免同批新建流程阻断后续行；每组调库日志保存本行所选主体的证券快照。
- 独立分页按当前页批量读取主档和评级主体。校验回写后使用本次已读明细组装首屏，复用证券主档、关联主体和自选权益人，仅补查首屏未读取的代码。自选候选分页使用 `batchSecurityPoolAdjust/querySelfSelectedRightsHolderPage`。明细返回 `relatedCompanyCode/relatedCompanyName`、`relatedRatingCompanies`、`selfSelectedRightsHolderCode/selfSelectedRightsHolder`、`securityType/absFlag` 及有效 `ratingCompanyCode/ratingCompanyName/ratingCompanyInnerRating`。校验结果展示有效主体全称/代码；联动、互斥、关联项展示来源导入行选择。独立清空入口的债券使用当前有效主体及默认候选。
- **未勾选**允许联动与互斥：结果中仅保留手工项
- **勾选**后保留完整展开项（与批量一致）
- 可调整手工项先保留完整单笔候选（含产品库快速资格及信用债简易资格），再通过 `BatchAdjustFlowOptionHelper.appendConfiguredBatchFlow` 加入目标池配置的批量调入或调出流程，并将其设为唯一推荐。复用本次已加载的池配置。
- 仅配置批量流程 ID 或 Key 时追加，未配置不新增批量无需审批候选并保留单笔推荐。同一流程定义的快速与批量选项按类型分别保留。满足快速资格即豁免本次信评报告及其他附件，与选择快速、一般、特殊或批量流程无关；行级 materialExemptionType 随校验结果和提交明细透传，切换流程不撤去提示，同组配套项跟随主项。
- 提交保留所选流程 ID/Key/类型，透传行级材料豁免依据，复用单笔材料规则；不再禁用产品库快速及材料豁免。批量推荐不覆盖操作员手动选择，不展示合同投资范围确认提示。
- 校验结果「调整类型」：手工主项 **Excel导入**（不对齐单笔「手工调整」；对齐批量渠道专属命名「手动批量调整」）；联动/互斥/关联同名
- 同组主券、联动、互斥、关联项的原业务失败原因完整保留，统一可提交；仅无法识别实际证券或目标池等数据错误阻断整组，不影响其他有效行。
- 提交：按来源导入行构建请求，通过 `BatchSecurityAdjustSubmitService` 提交，直通组批量写入调库日志、初始步骤、各笔证券快照和池状态，ABS 沿用身份确认、落池和同步提醒顺序，手工主项 `adjust_type=Excel导入`（联动/互斥/关联由 `resolveAdjustType` 落各自类型）
- 证券调入项的分析为空时，按发债主体集中查询近 180 天最新有效分析，正文和原始来源时间一起入快照。已有正文优先保留。
- 提交保留参数、来源明细一致性、评级主体合法性及关联组完整性检查；Excel 不因配套互斥调出可行性或报告必填再次阻断，已提供的报告仍检查引用有效性。人工审批和直通最终落池均由同组 Excel 主项批次识别来源，继续复核在途和重复调入。证券和目标池仍必须存在，数据库写入异常仍整批回滚。
- 调入落池前重新检查是否已有在池记录。证券调出项已不在库时按已完成处理。原流程选择与审批步骤继续沿用。

### 4.2 主体导入

- 目标池按 Excel 池名解析为启用的非 CRMW 叶子池，并检查 Excel 导入权限。主体校验和提交使用解析到的目标池。

- 上传和每次校验均按当前导入条件分阶段批量读取主体，每批最多 500 个不同条件。先查信用代码，仅为未命中的行继续查主体代码和名称；高优先级一对多直接报错，不进入下一级。原查询值随结果返回，精确比较由数据库完成；不对原查询值做 SQL 去重，避免大小写不同的输入在不区分大小写的排序规则下合并。匹配主体代码在 Java 中去重，行循环不再查询公司简介。
- 完整校验使用本次匹配的主体资料，一次读取投资池配置、池关系及导入权限，按批查询在池状态、在途节点和手工流程占用的池。观察池、全局禁止池及主体在 15/23 号池状态由有效在池记录判断。容量按涉及的池汇总，开放日和冻结期所需入池时间按本次规则范围读取。
- Excel 调入和独立清空涉及 17 号池时，批量读取近一年认可机构低外评，按每行预计调库状态执行三条件。Excel 调出跳过 17 号池的出库三条件，无需读取外评。每次重新校验实时取数。主体校验回写后用本次已读明细返回首屏，沿用每页 20 条和原明细顺序。上传上限为 2000 行，主体代码每 500 个一批。

- 主体匹配统一读取 `ais_inv_ods.wind_compintroduction`，去除输入首尾空格后按以下顺序精确查询：① 统一社会信用代码对应 `REGISTERNUMBER`（一对一）；② 主体代码对应 `COMP_ID`；③ 主体全称对应 `COMP_NAME` 或 `COMP_SNAME`。每一级未填写或未命中才进入下一级，唯一命中后即停止并回填明细 `fld001`，忽略低优先级条件。全部未命中或三项均为空时记录行级失败；信用代码异常对应多个主体或名称重名时明确报错，不任取一条。上传及重新校验均执行本规则，相同条件在本次处理中复用结果；最终代码参与重复检查，重新校验后的代码同步持久化。统一社会信用代码存 `fld005`，明细返回 `unifiedSocialCreditCode`。
- 每行 Excel → 一主体 + 一目标池 + 方向，调用禁投池主体完整校验。清空候选中，主体按在池记录的 `security_type=company` 识别，名称直接读状态表。主体详情与提交按公司简介 `COMP_ID` 读取名称、类型和地址，未发债主体同样可处理。
- 校验结果的主体代码、全称和类型由主体主数据统一回填，覆盖可调整和不可调整的手工项以及主体联动项。名称列空值留白，不使用主体代码代替名称。重新校验会更新本批保存的校验快照。
- 联动/互斥同样受「允许联动与互斥」选项过滤
- 主体 Excel 联动调入黑名单质押库（17）通过校验时，「调整说明」默认显示「联动调整调入」。有实际校验提示时按列表显示。
- 主体有在途流程时，校验提示「主体存在进行中的调库流程」，有当前节点时一并显示。由主项校验失败导致联动项不可调整时，说明显示「“投资池名称”校验未通过」。
- 主体 Excel 调出勾选允许联动时，按已配置的调出联动池展开。黑名单质押库（17）有该主体的在池记录时，生成联动调出项，跳过该池的出库三条件。在途流程仍拦截同组调出。
- 可调整的导入主项保留单笔主体调库校验返回的候选，与证券导入共用批量候选追加方法。目标池对应方向配置了批量流程 ID 或 Key 时，将批量流程设为唯一推荐；批量流程留空或选「不需要审批」时，沿用单笔校验结果。单笔候选为空时，候选列表仅包含已配置的批量流程
- 提交按本批服务端校验结果确认可提交项，按主体分组调用 `BatchCompanyAdjustSubmitService.submit`，遵循操作员选定的流程。配套互斥调出可行性和报告必填与证券 Excel 使用同一提示放行口径，已提供的报告仍校验引用。
- 主体导入和清空通过独立批量提交服务实时读取主体主档及池配置，同一流程在本次提交读取一次快照，批量写入日志、初始步骤和直通池状态。直通和终审复核主体及目标池是否存在。同组联动、互斥项沿用 Excel 口径。调入时仍复核是否已在目标池或有在途流程。主体显式导入调出时若已出池，按已完成处理。

### 4.3 提交规则

- 证券提交按本批实际提交的代码从数据库集中读取主档、关联评级主体和自选权益人，同一目标池只复核一次导入权限。编辑主体时重新查询当前行的候选；清空出库时集中读取主档和候选，ABS 优先采用本次查到的已占用主体。证券导入和清空共用本次读取的池配置、主档与评级候选。直通批量落池，待审批、产品库快速资格及带附件引用的组按原路径提交。
- 证券、主体的调库校验结果在序号左侧显示复选框。每次校验默认全选可调整项，表头可全选或取消全选。可调整项逐条勾选，不可调整项禁选。
- 后端按校验快照逐条核对勾选项，拒绝空选、重复选择及未通过校验的行。同券各市场代码也按勾选结果提交。已选手工项按所选流程提交。同一来源行仅勾选配套项时，由首个已选配套项沿用来源主项的默认流程，作为 Excel 调库主项发起。
- 确认弹窗按来源行列出单独勾选的配套项代码，并只读显示这些项将沿用的默认流程。
- 成功后一次更新实际提交项对应的 Excel 来源明细，保留 `ref_id`，本批次标记为已提交。
- 提交成功后的响应回显导入主项本次所选流程，批次校验快照保留校验时的流程
### 4.4 清空目标池

- 两种导入类型共用独立按钮。弹窗通过投资池树设置条件，点击「查询」应用筛选，点击「重置」恢复全部可操作投资池。表格分页展示序号、投资池全称、在池主体数量和在池债券数量。序号跨页连续，支持跨页勾选启用叶子池。
- 点击「确认清空」后弹出警告，显示所选池数量和直通出库影响。二次确认后才提交，取消或关闭提示时保留勾选。
- 后端按所选池集中读取生效成员、池配置和所需校验数据，分别执行主体、债券单笔调出规则，并展开联动、互斥和关联项。有校验失败时整次操作不落库，返回池、对象和失败原因。目标池要求调出研究报告且未满足历史报告豁免时，提示通过单笔调库处理。
- 通过后固定走「无需审核审批流程」（`bond:no-approval`），记录开始、发起和结束步骤，直接生效。主项记录为「清空目标池」，配套项按实际调整类型记录。流程步骤、调库日志与池状态在同一事务提交。固定流程未发布或无法直通时，提示检查流程配置。

### 4.5 定时调库保护

- 按调库批次号匹配已生效的 Excel 调入流水，识别当前在池的导入主项及同批关联、联动调入项。自动调库跳过受保护的出池状态，包括到期出池及互斥配套出池。
- Excel 主体调入、调出按主体和依据池取最近一笔生效决定，包含同批联动及互斥产生的主体调整。普通债跟随时跳过评级、到期天数和报告校验，补入仍排除主档状态为 D 的债券，并校验池关系及在途状态。ABS 继续由独立任务按原规则处理。
- Excel 主体调入派生的在池债券标记「Excel主体跟随」，到期出池和其他自动调库按保护规则跳过。主体明确通过 Excel 调出的池撤销普通债跟随记录，也禁止其他映射重新补入该池。跨池跟随失去全部主体依据时同样撤销。债券独立入池记录继续生效。
- 主体债入池规则提醒按当前在池记录 ID 跳过 Excel 导入生效的记录（含同批关联、联动调入）及「Excel主体跟随」债券。同券其他来源的在池记录继续复核。
- CRMW 专用 Excel 导入生效的当前组合及同批配套调入受到期自动出池、关联禁投出库及规则提醒任务保护。其他任务的 Excel 排除范围见[定时任务管理](29-scheduled-task.md#excel-导入的在池保护)。

## 当前市场口径

市场按当前代码在 `rrs_securityinfo.market` 的本地市场值校验（外部导入与 Wind `EXCHMARKET` 保持一致），银行间使用 NIB；临时代码使用登记表市场。关联券其他市场不使当前代码通过市场限制。批量候选直接按主档市场筛选，临时代码用登记表 EXISTS 筛选，展示按当前页批量查询唯一市场，避免关联连接重复分页或逐行市场查询。CRMW 导入复用证券主档缓存，同一代码的市场只查询一次。缺失、重复或不支持的映射报出具体代码。


## ABS 跨池唯一主体身份

- 仅 ABS 使用多主体逻辑。普通权益人查询限定 `s_info_typecode IN (115004000, 115203000, 115200000, 115201000)`；全市场自选主体保持现有来源。候选一次返回名称、代码、内评、认可机构最新外评及对应机构，选择后复用已查询数据；动态池状态不缓存。
- 同一 ABS 的所有有效在库和未结束申请（00/11）只能使用同一个主体代码。自选优先；同代码的不同关系角色或选择方式不算更换身份。该约束对单券、批量、Excel、禁投 ABS 和标的为 ABS 的 CRMW 申请均不可绕过。
- 在途身份保存在申请快照，提交不更新主档五字段。审核通过或直通生效时，在同一事务内更新 `issuer/issuer_code/rating_bondissuer/rating_bondissuer_agency/inner_issuer_rating` 并落池；驳回、撤回不改主档。
- 人工申请审核通过或直通成功入库后永久固定主体代码，全部出库且流程结束也不能更换。主体联动自动入池只生成 audit_status=00 的待确认调库日志，暂不写入 ip_pool_status 和主档五字段，也不形成永久绑定；研究员确认主体后才转为 audit_status=20 并正式入池，成功确认后才固定身份。此前仅有驳回或撤回且从未成功确认的申请不形成永久绑定；未结束申请仍占用本次主体。主档持续保留已确认身份，同一主体的名称和评级允许更新，历史详情保留原申请快照。
- 主体选择和只读查询不因身份占用提前报错；已有在库/在途主体冲突，以及同一批内同一 ABS 选择不同主体，都在下一步以 `canAdjust=false`、`failReasons` 返回，展示于“调整说明”。冲突组的联动、互斥和关联市场项同时不可调整，其他独立证券继续校验。Excel 提示放行、放开规则均不可绕过；正式提交及最终审批继续强制校验主体。提交和审批通过前查询当前在库及在途身份并校验一致性，不增加数据行锁。
- ABS 申请阶段财报查询和独立保存通过 `selectedRatingCompany` 使用本次选择；未选择时返回空财报，不回查证券代码或历史主档，无主体不允许保存。切换主体前保存原主体尚未保存的财报修改。
- ABS 使用适用的一般或特殊入库流程，简易入库及产品库快速入库资格判为不匹配。

## CRMW 普通池入口边界

CRMW 凭证可在证券池调整、批量调整和证券池 Excel 导入中按单券办理。存量证券批量调整也支持凭证，目标限定在债券产品库。前三个入口开放 CRMW 池作为目标池，沿用原调库校验。单券审批通过后写入 `ip_pool_status`。凭证与标的组合继续走专用 CRMW 调库，状态写入 `ip_pool_status_crmw`。 CRMW 专用批量调入仍从 `bond_product1_root`（债券产品库1）及其下级池的有效在池证券组成候选。清空目标池按单笔出库规则拦截失败项。

## 已查询数据复用

- 权益人、担保人或自选权益人候选已带回主体代码、名称、内评、认可机构最新外评及机构；选池、校验、提交通过 `selectedRatingCompany` 传递所选主体及普通/自选名称，后端直接使用，不重复查询候选或评级
- 单券页面传递已加载的 `securityInfo`，校验、提交及快照共用；批量仍读取实际需要的完整证券信息，同批主体比较直接使用页面传入类型和主体代码，不逐项复查主档
- 财报查询/保存直接使用已知主体代码，保存后返回本次记录，不逐期回查；当前在库、在途及同一 ABS 主体一致性仍按业务时点查询
