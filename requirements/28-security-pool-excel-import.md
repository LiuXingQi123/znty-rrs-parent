# 证券池 Excel 导入需求说明

> 前端页面：`security_pool_excel_import.html`  
> 后端前缀：`/api/v1/securityPoolExcelImport`  
> 公共模板下载：`/api/v1/commonFile/downloadTemplate`  
> 角色定位：具备投资池 `excel_importable` 权限的用户，通过 Excel 批量发起**证券**或**主体**池调入/调出。

### 同券关联市场范围

同券关联市场与投资池投资市场共用 `MarketCode` 集合（`SSE/SZSE/NIB/BSE/COMPANY/OTC/HKEX/QDII/JWCW/UNKNOWN/OTHER`），不另设白名单。先按 Wind `EXCHMARKET` 筛选主代码和关联代码，再查询本地主档；范围外代码不参与关联展示、关联校验和关联出入库，缺少主档不阻断，范围内缺少主档或市场仍报错。不按代码后缀或 `S_INFO_EXCHMARKET` 推断；目标池勾选的市场仍是逐券入池限制，不用于裁剪同券集合。证券池、ABS、CRMW、批量、Excel 及临时转正复用同一查询。

## 同券跨市场整组校验

同一非空 ISIN 的主券与关联券逐码校验，保留失败代码和具体原因；证券导入的业务失败作为调整提示，整组仍可提交。无法识别关联证券或目标池的数据错误仍阻断整组，不允许跳过这类关联券只提交其他市场。其他独立调库组不受影响。

“放开规则”由主券传递给所有关联券，仅跳过既有主体债入库矩阵规则；在途流程、市场、品种、到期、容量及其他硬限制仍按每个实际代码校验。

单笔提交携带基本信息已查询的 `relatedMarketCodes: [{ windCode, marketCode }]`；后端直接使用传入集合核对各目标池的调入明细是否带齐主券及关联券，提交阶段不再查询同券关系。批量及 Excel 入口复用本次校验结果中的实际代码集合。逐券活动流程检查继续执行。

## 1. 页面概览

单页工作台：上方双卡 + 下方 Tab（导入明细 / 调库校验结果）。

1. **导入参数**
   - **导入类型**：证券 / 主体（上传后锁定）
   - **调整方向**：调入 / 调出
   - **导入选项**：首先清空目标池；**允许联动与互斥**（仅证券展示；主体始终按禁投池展开）
   - **调整原因**
   - **不选目标池**（目标池由 Excel 父池/子池名称解析）
2. **下载模板并上传**
   - 两个下载按钮：**下载证券模板** / **下载主体模板**
   - 拖拽上传 xls/xlsx（≤5MB），按当前导入类型解析
3. **导入明细** Tab：行级校验状态、筛选、分页；证券行可选择担保人/权益人、ABS 自选权益人并显示主体内评；操作：重置 / 校验
4. **调库校验结果** Tab：对齐证券池批量调整列（简称/代码/池/调整类型/方向/审批流程/说明/可调整）；操作：重新校验 / 提交
5. **提交** → 弹出「选择调库流程」对话框（与批量调整一致）

### 1.1 模板列

| 类型 | 模板编码 | 列 |
|------|----------|----|
| 证券 | `security_pool_import` | 父池名称、子池名称、证券名称、证券代码 |
| 主体 | `company_pool_import` | 父池名称、子池名称、统一社会信用代码、主体全称、主体代码 |

不再包含：市场类型、证券品种、调整人、调整时间。

目标池由「父池名称 + 子池名称」解析为启用叶子池（主体根池允许父池为空）；每行可对应不同池。

证券模板不填写评级主体。上传后在「导入明细」中选择，控件和候选口径与「证券池批量调整—可选证券」一致：

- **担保人/权益人**：读取当前证券的四类关联主体，默认选中第一条，并显示名称、关系类型和最新内评。
- **自选权益人**：仅 ABS 展示，按主体代码或名称查询全市场有效主体；无需与当前证券存在关联。
- **主体内评分**：ABS 自选权益人优先；未选择自选权益人时使用关联主体。清除自选后恢复关联主体内评，不清除原关联选择。
- 各导入行独立保存担保人/权益人和 ABS 自选权益人。同一证券代码导入不同池时，上传默认值相同，但修改或清除某一行不影响其他行，翻页和刷新后仍保留各行选择。修改后本批所有行回到待校验，旧校验结果和流程选择清除，须重新校验。
- 默认第一条只在上传时初始化，后续分页和校验不覆盖手动选择或清除。ABS 必须有关联权益人或自选权益人；非 ABS 有关联主体时必须选择，无关联主体且单券规则不要求选择时允许留空。
- 旧六列模板仍按前四列读取，Excel 中的主体全称和代码不再参与选择；已提交批次不可修改主体选择。

## 4. 校验与提交口径（分证券/主体两分支，复用既有服务）

Excel 层负责：模板/临时表、父子池解析、`excel_importable` 权限、页面评级主体选择及导入类型分支编排。
**调库可行性与落库逻辑不再自写简化版**，分别委托：

| 分支 | 校验 | 提交 |
|------|------|------|
| 证券 | `SecurityPoolAdjustService.checkExcelAdjust`（原规则完整执行，业务失败作为可提交提示，含产品库快速资格） | `SecurityPoolAdjustService.addExcelImportAdjustLogList` |
| 主体 | `ForbiddenPoolAdjustService.checkCompanyAdjust` | `ForbiddenPoolAdjustService.addCompanyAdjustLog` |

主体导入和“首先清空目标池”的主体出库均复用主体落池链路：主体出入任意目标池，符合范围的旗下债券同方向出入同一池，日志共用主体批次；仅审批通过（或直通生效）才落地，失败整批回滚。

### 4.1 证券导入

- 每行 Excel → 一券 + 一目标池 + 方向，调用完整证券调库校验（含联动/互斥/关联码/流程候选）
- 原校验规则保持不变，执行结束后 Excel 专用入口将证券和目标池均可识别的整组结果设为 `canAdjust=true`，保留原 `failReasons` 作为“调整提示”；禁止池、调入限制池、容量、在途等原业务未通过项同样可提交，并继续生成原流程候选和追加批量推荐。不能识别证券、目标池或同组关联证券的数据仍不可提交，不伪造落库对象。
- 该放行口径仅用于证券导入行及其同组配套项；主体导入、首先清空目标池的出库、单笔和两个普通批量入口不变。
- 上传按与批量调整相同的关系优先级及最新内评排序，批量查询默认首条主体。页面通过代码保存选择，名称由服务端回填；不按 Excel 名称解析，不自动把无效关联选择转换为自选角色。
- ABS 关联权益人写入 `rightsHolderCode`，全市场自选权益人写入 `selfSelectedRightsHolderCode`，两者分别保存且自选优先评级；非 ABS 写入 `guarantorCode`。每次校验/提交重新复核候选资格，复用完整单券调库规则计算可调入池。ABS 最终采用的权益人（自选优先）无内评时，调入信用债分级库的校验提示“所选权益人无内评分”，与单券调整一致。
- 修改、校验、提交、取消均锁定同一批次，避免交叉执行。主体修改后清空本批行级校验及 `result_json`，即使客户端回传旧 `checkItems` 也不能绕过重新校验。
- 提交从本批已通过校验的持久化明细读取各行选择，按 `sourceItemId` 分组。同一证券的不同导入行允许选择不同主体，不校验跨行选择一致性；本行的主项、联动、互斥和关联项共用该行选择及流程。先统一复核已有在途流程，再逐行落库，避免同批新建流程阻断后续行；每组调库日志保存本行所选主体的证券快照。
- 明细返回 `relatedCompanyCode/relatedCompanyName`、`relatedRatingCompanies`、`selfSelectedRightsHolderCode/selfSelectedRightsHolder`、`securityType/absFlag` 及有效 `ratingCompanyCode/ratingCompanyName/ratingCompanyInnerRating`。校验结果展示有效主体全称/代码；联动、互斥、关联项展示来源导入行选择。首先清空目标池自动生成的出库成员不来源于 Excel 行，仍沿用原有默认主体逻辑。
- **未勾选**允许联动与互斥：结果中仅保留手工项
- **勾选**后保留完整展开项（与批量一致）
- 可调整手工项先保留完整单笔候选（含产品库快速资格及信用债简易资格），再通过 `BatchAdjustFlowOptionHelper.appendConfiguredBatchFlow` 额外加入目标池配置的批量调入/调出流程，批量为唯一推荐；证券池批量、存量证券批量共用该方法。复用本次已加载池配置，不增加查询。
- 仅配置批量流程 ID 或 Key 时追加，未配置不新增批量无需审批候选并保留单笔推荐。同一流程定义的快速与批量选项按类型分别保留。满足快速资格即豁免本次信评报告及其他附件，与选择快速、一般、特殊或批量流程无关；行级 materialExemptionType 随校验结果和提交明细透传，切换流程不撤去提示，同组配套项跟随主项。
- 提交保留所选流程 ID/Key/类型，透传行级材料豁免依据，复用单笔材料规则；不再禁用产品库快速及材料豁免。批量推荐不覆盖操作员手动选择，不展示合同投资范围确认提示。
- 校验结果「调整类型」：手工主项 **Excel导入**（不对齐单笔「手工调整」；对齐批量渠道专属命名「手动批量调整」）；联动/互斥/关联同名；清空主项 **Excel清空**
- 同组主券、联动、互斥、关联项的原业务失败原因完整保留，统一可提交；仅无法识别实际证券或目标池等数据错误阻断整组，不影响其他有效行。
- 提交：按来源导入行构建请求，通过 `addExcelImportAdjustLogList` 复用证券调库提交步骤，手工主项 `adjust_type=Excel导入`（联动/互斥/关联由 `resolveAdjustType` 落各自类型）
- 提交保留参数、来源明细一致性、评级主体合法性及关联组完整性检查；Excel 不因重复业务申请、在途、配套互斥调出可行性或报告必填再次阻断，已提供的报告仍检查引用有效性。人工审批和直通最终落池均由同组 Excel 主项批次识别来源，不再用原业务规则拒绝。证券和目标池仍必须存在，数据库写入异常仍整批回滚。
- 重复调入已在库证券时，先软删除旧有效状态再写新状态，避免重复有效在库记录；证券导入的调出项已不在库时按已完成处理。原流程选择与审批步骤保持不变，允许提交不代表自动跳过审批。

### 4.2 主体导入

- 上传和每次校验均按当前导入条件分阶段批量读取主体，每批最多 500 个不同条件。先查信用代码，仅为未命中的行继续查主体代码和名称；高优先级一对多直接报错，不进入下一级。原查询值随结果返回，精确比较由数据库完成；不对原查询值做 SQL 去重，避免大小写不同的输入在不区分大小写的排序规则下合并。匹配主体代码在 Java 中去重，行循环不再查询公司简介。
- 完整校验复用本次匹配返回的主体全称、简称和编码，不再逐主体查询详情、债券总数及主体基础信息。投资池配置和池关系在首条进入完整校验时加载一次，通过 `CompanyAdjustCheckContext` 显式传递；相同目标池的 Excel 导入权限检查同批复用。上下文不写服务字段或静态变量，重新校验重新读取，单笔入口及提交前复核保持实时查询。
- 池状态、在途流程、容量、债券互斥展开等完整规则仍逐项执行，本优化不代表整个调库过程只有几次 SQL。不清空目标池、2000 个不同主体均在首项命中时，上传与一次校验合计查询公司简介 8 次；3000 个主体的内部算法测试为每次 6 批，上传上限仍为 2000 行。清空目标池及提交时的主体复核仍使用既有链路。

- 主体匹配统一读取 `ais_inv_ods.wind_compintroduction`，去除输入首尾空格后按以下顺序精确查询：① 统一社会信用代码对应 `REGISTERNUMBER`（一对一）；② 主体代码对应 `COMP_ID`；③ 主体全称对应 `COMP_NAME` 或 `COMP_SNAME`。每一级未填写或未命中才进入下一级，唯一命中后即停止并回填明细 `fld001`，忽略低优先级条件。全部未命中或三项均为空时记录行级失败；信用代码异常对应多个主体或名称重名时明确报错，不任取一条。上传及重新校验均执行本规则，相同条件在本次处理中复用结果；最终代码参与重复检查和清空差集，重新校验后的代码同步持久化。统一社会信用代码存 `fld005`，明细返回 `unifiedSocialCreditCode`。
- 每行 Excel → 一主体 + 一目标池 + 方向，调用禁投池主体完整校验。清空目标池按状态表 `security_type=company` 筛选主体，名称直接读状态表，不新增公司简介关联，不依赖证券主档中的主体占位行。详情与提交按公司简介 `COMP_ID` 读取名称、类型和地址；不再关联发行人表，未发债主体同样可处理。
- 校验结果的主体代码、全称和类型由主体主数据统一回填，覆盖可调整和不可调整的手工项以及主体联动项；旗下债券互斥项保留债券自身代码、简称和类型。名称列空值留白，不使用主体代码代替名称。重新校验会更新本批保存的校验快照。
- 联动/互斥同样受「允许联动与互斥」选项过滤
- 无流程候选时注入标准入/出库（缺省回退批量配置）
- 提交：按主体分组调用 `addCompanyAdjustLog`（含审批通过后旗下债券同步等既有逻辑）

### 4.3 提交规则

- 仅提交 `canAdjust=true` 的校验结果项
- 证券导入的原业务未通过项已在服务端统一转为可提交状态，前端原提交筛选会携带这些项；“调整说明”按有无 `failReasons` 独立展示“调整提示（共 N 项）”，不再依赖不可调整状态。校验原因及可提交状态均写入导入快照，重新打开批次不丢失提示。
- 手工项可在表格/弹窗中选择流程；联动/互斥随同组提交
- `clearTarget`（仅调入）：校验时生成「清空出库」项（差集：在池但不在本批 Excel 的成员 → 批量调出）；非本批编码在途跳过不纳入；本批证券编码在途保留为导入行调整提示。清空主项及同一来源的联动、互斥和关联项一同提交出库，清空出库仍执行原阻断规则，先清空出库再导入。

## 当前市场口径

市场按当前代码在 `rrs_securityinfo.market` 的本地市场值校验（外部导入与 Wind `EXCHMARKET` 保持一致），银行间使用 NIB；临时代码使用登记表市场。关联券其他市场不使当前代码通过市场限制。批量候选直接按主档市场筛选，临时代码用登记表 EXISTS 筛选，展示按当前页批量查询唯一市场，避免关联连接重复分页或逐行市场查询。CRMW 导入复用证券主档缓存，同一代码的市场只查询一次。缺失、重复或不支持的映射报出具体代码。
