# CRMW关联禁投自动出库

> 入口：定时任务管理；任务名称：CRMW关联禁投自动出库；编码：`crmw_forbidden_auto_out`
> 实现：`CrmwForbiddenAutoOutService` 负责扫描和本类单条注解事务；使用 `CrmwForbiddenAutoOutMapper`，复用原 `CrmwPoolAdjustMapper.addAdjustLog` 写日志

## 1. 业务角色与边界

1. **标的债券：A 公司发行的债券**，是接受信用保护的对象
2. **CRMW 凭证：由 B 机构创设／提供信用保护**，与标的债券形成在库组合
3. 标的债券自身、发行主体 A、CRMW 凭证自身、创设／保护主体 B 任一已在有效禁止库，就退出对应在库组合

主体分别来自标的与凭证当前主档的 `issuer_code`，不能互换，不以名称匹配，不扩展担保人或 ABS 未确认权益人。双方主档和唯一主体代码须完整；主档缺失、凭证类型错误或主体代码缺失／为多值时，记录该组合错误并继续处理其他组合，不使用推断或默认值替代来源数据。

本任务只负责已有组合清退。禁止库入库日志由原手工、导入或自动任务产生，不重复生成；不因 B 被禁投而把 A 或标的债额外加入禁止库。禁止库调出后不自动恢复组合。不修改 CRMW 调入校验及最终审批复核，不取消或改写在途申请；因此仍可能在两次任务之间重新入库，下一轮再清退。

## 2. 扫描与命中规则

1. 扫描 `ip_pool_status_crmw` 中 `audit_status=20`、`is_deleted=0`、`pool_type=crmw`，且投资池未删除、`pool_type=crmw` 的实际组合，不限制为固定18池
2. 禁止库依据只认 `ip_pool_status` 中未删除、审批通过的状态，且目标池未删除、`pool_type=forbidden`，不依赖固定15池
3. 观察池、重点观察名单、黑名单质押库均不等于禁止库；低内评也不单独触发本任务，这些风险提醒仍由 [47](47-crmw-rule-alert.md) 负责
4. 四类命中原因合并到同一实际组合的出库记录；同一凭证绑定多个标的、同一标的绑定多个凭证时，逐个处理受影响组合；同一组合在不同池分别退出
5. 禁投为本任务的硬清退条件，不执行人工流程的锁定、冻结期、开放日、调出限制或到期日校验，不因已到期／退市漏掉仍在库的组合
6. 只软删除扫描到的原状态主键及对应完整组合，不物理删除历史或绑定资料；原状态已退出时不再生成出库日志，不误删后续重新入库的新状态

## 3. 执行结构与性能

1. `execute()` 包装计时、日志、异常和任务结果；私有 `doAutoOutForbidden()` 一次读取候选并逐组合处理，`autoOutCombination()` 准备日志后，通过本任务的Spring代理调用公开方法 `editCrmwForbiddenOutByJob()`
2. 组合表通常一千多条、最多不到一万条，一次读取全部有效组合，移除游标、分页参数、LIMIT和ORDER BY；候选SQL只关联组合状态和投资池
3. 本轮标的和凭证代码去重后单表读取证券主档，再把双方主体并入去重代码集，一次读取对应禁止库状态；不逐组合查库，不把百万级主档、投资池和多类状态拼成复杂SQL
4. 每个命中组合使用独立事务，状态和日志同时提交；该条写入失败时只回滚该条，记录错误并继续，不影响此前或后续正常组合
   单条公开方法使用 `@Transactional(rollbackFor = Exception.class)`，扫描和出库均留在任务类。通过 `ObjectProvider<CrmwForbiddenAutoOutService>` 在执行时取得任务代理，避免 `this` 自调用绕过事务，也不需要开启循环依赖。任务入口不加整体事务，每次代理调用单独提交；单条方法不捕获写入异常，先由Spring回滚，外层再记录并继续。不使用TransactionTemplate，不依赖CrmwPoolAdjustService
5. 下一轮重新读取当前有效组合，已清退状态不再进入候选，覆盖存量不一致和各种入库入口产生的后续变化，无需各禁止库入口新增实时清退逻辑
6. 任务完成后汇总扫描、已提交出库及失败数量；有单条失败仍完成本轮，错误明细在过程日志展示。只有候选、主档或禁止库公共查询不可用时，才返回任务级失败

## 4. 日志与现有功能

- 复用 `ip_adjust_log`，记录 `adjust_type=自动调整`、`adjust_mode=调出`、`audit_status=20`、`pool_type=crmw`、`adjuster_id=0`、`adjuster_name=系统`
- 凭证、标的和所在池身份完整保留，按“凭证＋标的＋池＋方向”生成 `CRMW` 批次号；只赋 `adjust_reason`，`adjust_advice` 保持NULL
- 出库原因包含全部禁投对象代码，供 CRMW 调整历史及恒生增量导出读取；任务过程日志不输出批次号
- 不新增表、Controller、业务页或待办Tab；使用现有定时任务配置、执行历史和业务调库历史
- 原 CRMW 规则提醒按其下一轮扫描失效已出库组合的待处理提醒，本任务不改写提醒表或已处理记录

## 5. 调度与依赖评估

1. Demo默认关闭，Cron为 `0 7/10 * * * ?`，每小时第7、17、27、37、47、57分执行，无需扩展参数
2. 第0分的在池主体补债、第2分的Wind换码、第5分的ABS对账完成后再检查；避开第40分临时代码替换、第13分CRMW提醒和每6分钟增量导出的同秒触发
3. 23:07在23:05到期CRMW之后，23:27在23:20补债、23:25ABS对账之后；01:07早于01:10／01:20全量导出，09:07早于09:13CRMW提醒
4. 不同任务没有编排或全局互斥，cron错开不代表前序已完成；需按实际耗时留间隔，导出前也不能据此承诺零延迟一致
5. 禁止库刚生效到下一轮任务成功完成之间，组合可能仍可见；当前只做定时清退，调入与审批校验后续单独完善
